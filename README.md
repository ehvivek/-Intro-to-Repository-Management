## 📘 About This Repository

This repository is part of the **[GitHub Skills](https://skills.github.com/)** learning pathway — a hands-on course designed to teach developers how to **manage repositories like a pro**. Rather than just reading documentation, this challenge walks you through real-world scenarios involving team collaboration, code protection, and security workflows.

## 🗂️ Topics Covered

| # | Topic | Description |
|:-:|:------|:------------|
| 01 | **Repository Rulesets** | Enforce branch naming conventions, commit requirements, and push restrictions across the repository |
| 02 | **Branch Protection** | Require status checks, pull request reviews, and prevent force pushes to `main` |
| 03 | **CODEOWNERS** | Automatically assign reviewers based on file paths and ownership mapping |
| 04 | **Security Policies** | Create `SECURITY.md` to define how vulnerabilities should be reported and handled |
| 05 | **Collaboration Workflows** | Structure team workflows using issues, project boards, and milestone tracking |
| 06 | **Pull Request Management** | Define merge strategies, review requirements, and CI/CD integration for PRs |

## 🔐 Collaboration Best Practices

<details>
<summary><strong>🔀 Branching Strategy</strong></summary>
<br/>

- `main` — Production-ready, protected branch
- `feature/*` — New features and enhancements
- `fix/*` — Bug fixes and patches
- `docs/*` — Documentation updates

All changes flow through **pull requests** with mandatory code review before merging.

</details>

<details>
<summary><strong>✅ Code Review Standards</strong></summary>
<br/>

- Minimum **1 approving review** required before merge
- **CODEOWNERS** automatically requested for relevant file changes
- All CI checks must **pass** before merge is enabled
- Descriptive commit messages following **conventional commit** standards

</details>

<details>
<summary><strong>🛡️ Security Workflow</strong></summary>
<br/>

- Vulnerabilities reported via the process defined in `SECURITY.md`
- Dependabot enabled for **automated dependency updates**
- Secret scanning and push protection **active**
- Regular security audits through GitHub's built-in tools

</details>
